# 05 复盘

## 5.1 最难的问题

### ① 让"冲突"变成真推理，而不是查表

最初的写法很自然：目标时段被占 → 找下一个空闲时段 → 保存。这样代码里就是两个分支，
考官一眼就能看出模型没做决策。

真正让题目变难的是 R2：`19:00` 明明空闲，但距同账号 `18:00` 的排期只隔 60 分钟，违反"间隔 ≥120 分钟"。
于是模型必须把 `query_slots` 和 `check_rules` 两次结果合起来判断。
这个规则一加上，"空闲时段"和"合规时段"就不是同一个集合了，路径差异自然出现——
`run-02` 里模型自己推断出"19:00 必违规"，直接去校验 20:00，而不是逐个试。

**教训**：想让 Agent 真的"思考"，不是靠提示词要求它"多想想"，
而是让数据本身存在需要组合判断才能得出结论的结构。

### ② 工具失败的信息要能让模型自己修好

第一次跑 `save_fail_m01` 时，模型重试时漏传了 `slot`，工具返回
`TypeError: missing 1 required positional argument: 'slot'`。
模型看到这句话没法知道该补什么、能不能重试，最后任务直接失败。

改成在 `dispatch()` 里先做参数校验，返回结构化的错误：

```json
{"ok": false, "error": {
  "code": "bad_arguments",
  "message": "缺少必需参数：slot。本工具必需参数：asset_id, slot, deviation_from_required，请补全后重试。",
  "retryable": true
}}
```

重跑后，模型在下一步补全参数并成功（`run-07` 第 7→8 步）。

**教训**：工具的错误信息不只是给人看的，更是模型唯一的纠错输入。
写"参数错误"和写"缺 slot，必需参数是这三个，可以重试"，效果完全不同。

### ③ 推理模型的 `content` 是空的

接入 `qwen3.8-flash` 后第一次跑，`trace.json` 里所有 `decision_basis` 都是空的。
原因是推理模型把说明写在 `reasoning_content` 里，调用工具时 `content` 为空。

解决分两步：系统提示词要求"每次调用工具前用一句话说明理由"；
provider 层保留 `reasoning_content` 作为兜底，但只截取第一句，完整思维过程不落盘。

**教训**：换模型要重新验证输出结构，不能假设 OpenAI 协议里的字段都有值。

### ④ 还要分清楚"基础设施重试"和"Agent 重试"

题目明确写了"自动重试不视为 ReAct 决策"。所以 provider 里对 429/5xx 的重试必须和
"模型看到失败后决定再试一次"区分开：前者在 HTTP 层，记录为 `infra_retry`；
后者是模型的一个动作，出现在 trace 的步骤里。混在一起会让证据失效。

## 5.2 学习收获

1. **Agent 的能力上限很大程度上由工具契约决定**。工具返回什么、错误怎么说、有没有不该有的能力
   （比如 publish），比提示词写得多漂亮更影响结果。
2. **防呆要做在架构上，不要做在提示词里**。"不要发布"写在提示词里只是建议；
   把 publish 从工具表里删掉才是保证。
3. **可验证比能跑通更难**。让流程跑起来只要半天，让每个断言都能稳定复现要花更多时间，
   但后者才是"能拿出去给人看"的东西。
4. **证据要分层**。Mock 证明流程，真实模型证明决策，两者混在一起就是自欺欺人。
